# Paseo Workspace HQ (Штаб)

Полнофункциональный плагин центрального штаба для [Paseo](https://paseo.sh): проекты, сессии, интерактивные артефакты, мониторинг воркеров команды, системных служб и учет расхода моделей.

---

## Возможности

1. **Проекты и воркспейсы («Штаб»)**:
   - Иерархический список проектов, кастомные аватарки без ограничений размера (автоматическое кадрирование).
   - Сортировка сессий по времени последнего сообщения.
   - Умная генерация названий сессий в 1–3 слова с выбором модели.
   - Перенос сессий между проектами с сохранением контекста.
   - Поддержка нескольких параллельных чатов в одном воркспейсе с отображением их счетчика и списка в настройках.
   - Быстрое копирование нативной ссылки на чат (`paseo:///h/local/agent/<id>`) и его ID.

2. **Межсессионное взаимодействие (`bin/paseo-chat`)**:
   - Передача ссылок на чаты другим агентам для изучения контекста.
   - Утилита `bin/paseo-chat` (`paseo-chat ls`, `read <url-or-id>`, `send <url-or-id> <текст>`).
   - Нативная маршрутизация сообщений между агентами через очередь Paseo с автоматической фиксацией отправителя и режимом `steer`.

3. **Интерактивные артефакты**:
   - Автоматическое распознавание блоков кода (`html`, `svg`, `markdown`) в чатах и преобразование их в интерактивные карточки с песочницей и кнопками действий.
   - Галерея артефактов (`/surface/artifacts`) с фильтрацией по проектам, поиском и возможностью удаления ненужных карточек.
   - Автоматическая отправка новых HTML-страниц в Telegram через встроенный клиент Telegram Bot API без дублирования.
   - Ручная отправка любых артефактов в Telegram в один клик.
   - Опциональный облачный экспорт (S3 / rclone / WebDAV / Яндекс Диск).
   - Индексация готовых документов из папки `artifacts/` в корне проекта без захламления репозиторными файлами.

4. **Команда и воркеры (Workers Monitor)**:
   - Мониторинг изолированных сред разработчиков и агентов (LXC-контейнеры, Docker, cgroup v2).
   - Снятие метрик в реальном времени: нагрузка на процессор (с учетом лимита ядер), потребление ОЗУ, количество процессов, статус активности.
   - Плашка команды в шапке панели и полноэкранный диалог управления.

5. **Системные службы (Host Services)**:
   - Мониторинг ключевых systemd-служб и таймеров хоста без sudo и сторонних демонов.
   - Настраиваемый список отслеживаемых сервисов.

6. **Интеграция с Git**:
   - Поиск и клонирование репозиториев из GitHub и GitLab (включая приватные инсталляции) в один клик.
   - Автоматическое создание воркспейсов.

7. **Лимиты и расход моделей**:
   - Трекинг расхода токенов и баланса провайдеров (Claude, OpenAI, DeepSeek, Google Gemini, Antigravity).

## Установка

Плагин устанавливается штатной командой Paseo:

```bash
# Добавить и активировать плагин из локальной папки
paseo plugin add /path/to/paseo-hq

# Проверить статус
paseo plugin ls

# При внесении изменений в код
paseo plugin reload paseo-hq
```

## Инструкция для AI-агентов

В корне плагина находится файл **`AGENTS.md`** с подробным описанием правил работы для AI-ассистентов (Claude, Codex, Antigravity, Cursor):
- Как правильно размечать интерактивные артефакты (`html`, `svg`, `markdown`) в кодовых блоках.
- Где сохранять готовые файлы на диске проекта (`artifacts/`), чтобы они автоматически попадали в галерею.
- Как настраивать переменные Telegram и мониторинга для пользователя.

Если вы настраиваете рабочее место через AI-агента, просто попросите его:
> *«Прочитай AGENTS.md в плагине paseo-hq и настрой мне Telegram и мониторинг воркеров»*.

## Настройка конфигурации

Плагин работает из коробки с разумными значениями по умолчанию, но его можно полностью настроить под ваше окружение.

### 1. Переменные окружения

Задаются в профиле оболочки (`~/.bashrc` / `~/.zshrc`) или в конфигурации демона Paseo (`~/.paseo/config.json`):

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `PASEO_REPOS_DIR` | Корневой каталог для поиска и клонирования проектов | `~/repos` |
| `PASEO_ARTIFACTS_DIR` | Папка для хранения сохраненных артефактов и индексов | `~/.paseo/artifacts` |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота для отправки HTML и документов | *(отключено, если не задано)* |
| `TELEGRAM_CHAT_ID` | Chat ID в Telegram, куда отправлять документы | *(отключено, если не задано)* |
| `PASEO_CLOUD_UPLOAD_CMD` | Шаблон команды для облачного экспорта (S3/rclone) | *(отключено, если не задано)* |
| `PASEO_WORKERS_CONFIG` | Путь к файлу конфигурации воркеров | `~/.paseo/workers.json` |
| `PASEO_SERVICES_CONFIG` | Путь к файлу конфигурации служб | `~/.paseo/services.json` |

#### Пример отправки в Telegram:
```bash
export TELEGRAM_BOT_TOKEN="123456789:ABCdefGHIjklMNOpqrsTUVwxyz"
export TELEGRAM_CHAT_ID="987654321"
```
После этого карточки артефактов получают активную кнопку **«В Telegram»**, а все создаваемые HTML-артефакты автоматически прилетают в личные сообщения бота (где на iPhone открываются во встроенном Safari-просмотрщике Telegram).

#### Пример облачного экспорта:
```bash
export PASEO_CLOUD_UPLOAD_CMD='rclone copy {file} mycloud:artifacts/{project}/ && rclone link mycloud:artifacts/{project}/{name}'
```

### 2. Мониторинг воркеров команды (`~/.paseo/workers.json`)

Создайте файл `~/.paseo/workers.json` (образец лежит в `workers.example.json`):

```json
[
  {
    "id": "alex",
    "name": "Алексей",
    "avatar": "🧑‍💻",
    "role": "Fullstack Agent",
    "container": "alex-work",
    "user": "alex",
    "activityPath": "/run/workers/alex-status.json",
    "cgroupPath": "/sys/fs/cgroup/lxc.payload.alex-work"
  },
  {
    "id": "sergey",
    "name": "Сергей",
    "avatar": "👨‍💻",
    "role": "DevOps / Infra",
    "container": "sergey-work",
    "user": "sergey",
    "activityPath": "/run/workers/sergey-status.json",
    "cgroupPath": "/sys/fs/cgroup/lxc.payload.sergey-work"
  }
]
```

- `cgroupPath`: путь к cgroup контейнера (LXC или Docker), откуда читаются метрики CPU (`cpu.stat`, `cpu.max`), RAM (`memory.current`, `memory.max`) и число процессов (`pids.current`).
- `activityPath`: опциональный JSON-файл со временем последнего запроса агента и входа (`agentLast`, `lastMessage`, `lastSsh`).

---

### 3. Мониторинг служб хоста (`~/.paseo/services.json`)

Создайте файл `~/.paseo/services.json` (образец лежит в `services.example.json`):

```json
{
  "docker.service": ["Docker", "Демон управления контейнерами"],
  "nginx.service": ["Nginx", "Веб-сервер и обратный прокси"],
  "ssh.service": ["SSH", "Служба защищенного удаленного доступа"],
  "postgresql.service": ["PostgreSQL", "Основная база данных"]
}
```

Кнопка `[Server]` в верхней панели Штаба покажет интерактивную таблицу с их статусом в реальном времени.
